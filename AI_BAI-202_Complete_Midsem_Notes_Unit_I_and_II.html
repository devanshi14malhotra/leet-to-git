1. Introduction to AI

What is intelligence?

There is no single exact definition. Intelligence is usually described by the abilities it shows: dealing with new situations, solving problems, answering questions, devising plans, abstract thinking, communication, learning from experience, memory and planning, creativity, and making sense of ambiguous or contradictory messages. It is not about how fast information is processed, but about communicating effectively and learning new concepts.

What is Artificial Intelligence?

  • Simulation of intelligence in machines; the science and engineering of making intelligent machines, especially intelligent programs.
  • The study of systems that act in a way that, to any observer, would appear intelligent. AI does not have to copy biological methods.
  • AI deals with hard problems that humans and animals solve easily but for which we have no good algorithms: understanding spoken language, medical diagnosis, circuit design, learning, game playing, reasoning.
  • Kurzweil (1990): "the art of creating machines that perform functions that require intelligence when performed by people". Rich and Knight (1991): "the study of how to make computers do things at which, at the moment, people are better". Winston (1992): "the study of the computations that make it possible to perceive, reason and act".

2. Intelligent agents

Agent, sensors, actuators, effectors

An agent is anything that perceives its environment through sensors and acts upon it through actuators. It runs in a cycle of perceiving, thinking and acting.

TermMeaning
SensorDetects changes in the environment and sends the information on. Examples: eyes, ears (human); camera, infrared range finder (robot); keystrokes, file contents (software agent).
ActuatorComponent that converts energy into motion; responsible for moving and controlling a system. Examples: electric motor, gears, rails.
EffectorThe device that affects the environment. Examples: legs, wheels, arms, fingers, wings, display screen.
PerceptWhat the agent perceives at one moment; the full list so far is the percept sequence.
EnvironmentEverything around the agent that is not part of the agent; the situation the agent is in.

Types by body: human agent (eyes/ears, hands/legs), robotic agent (cameras, range finders, motors), software agent (keystrokes and files as input, screen as output).

Intelligent agent: the four rules

An intelligent agent is an autonomous entity that acts on an environment using sensors and actuators to achieve goals, and may learn from the environment. A thermostat is a simple example.

  1. It must be able to perceive the environment.
  2. Observations must be used to make decisions.
  3. Decisions must result in an action.
  4. The action must be a rational action.
  • Architecture: the machinery with sensors and actuators (robotic car, camera, PC).
  • Agent function: maps the percept sequence to an action.
  • Agent program: the implementation of the agent function.
  • Agent = architecture + program.

Rational agent

A rational agent has clear preferences, models uncertainty, and acts to maximise its performance measure over all possible actions. It "does the right thing". Rationality depends on four things:

  1. The performance measure that defines success.
  2. The agent's prior knowledge of the environment.
  3. The actions it can perform.
  4. The percept sequence to date.
RememberRational is not omniscient (it does not know everything, the environment may be partially observable), and not clairvoyant (it cannot predict a stochastic environment). So a rational agent is not always successful. In reinforcement learning, a good action earns a positive reward and a bad one a negative reward.

Types of agents (in increasing generality)

(a) Simple reflex agent

  • Acts on the current percept only using condition-action rules ("if obstacle detected then turn left"). No memory, no prediction.
  • Works only in fully observable, simple environments. Limits: very limited intelligence, rule tables can be too big, not adaptive, no knowledge of non-perceptual parts of the state.

(b) Model-based reflex agent

  • Keeps an internal state (a summary of the percept history) and a model of "how the world evolves" and "what my actions do". It can reason about parts of the world it cannot currently see.
  • Good for partially observable environments.
function ReflexAgentWithState(percept):
    state  = UpdateState(state, action, percept)
    rule   = RuleMatch(state, rules)
    action = RuleAction(rule)
    return action

(c) Goal-based agent

  • Has goals and picks actions by asking "what will the world be like if I do action A?" and whether that leads to the goal. Uses search and planning. Flexible, but slower because it reasons about the future.

(d) Utility-based agent

  • Goals are not enough when there are several ways to reach them. Uses a utility function f(state) → value ("how happy will I be in such a state?") to choose the action with the highest expected utility. Handles competing goals and trade-offs (short-term vs long-term).

(e) Learning agent

Improves over time from experience. Four components:

One-line summarySimple reflex = rules on current percept. Model-based = adds memory/internal state. Goal-based = adds goals and planning. Utility-based = adds a measure of "how good". Learning = can improve itself.

3. Turing Test

Proposed by Alan Turing in 1950 ("Computing Machinery and Intelligence") to replace the question "Can machines think?" with "Can machines behave intelligently?". Also called the Imitation Game.

Set-up and rule

  • Three rooms/terminals: a person, a computer and an interrogator. Communication is text-based so appearance and voice do not give the machine away.
  • The interrogator asks questions and tries to decide which respondent is the machine. The machine tries to fool the interrogator into believing it is the human.
  • If the interrogator cannot reliably tell them apart, the machine passes and is said to exhibit human-like intelligence.
  • Turing predicted that by 2000 a machine might have a 30% chance of fooling a lay person for 5 minutes. He suggested the main components of AI: knowledge, reasoning, language understanding, learning.

Significance

  • A landmark idea in AI; gave an operational definition of intelligent behaviour.
  • Raises philosophical questions about intelligence and consciousness.

Limitations (criticisms)

  • Tests imitation, not real understanding or thinking.
  • Does not test a machine's ability to understand context.
  • The test is not reproducible, constructive or amenable to mathematical analysis.
LinkThe Turing Test is the "acting humanly" approach. The Loebner Prize is its modern competition. ELIZA is the classic early example of a program that fooled some people.

4. Problem solving and solving problems by searching

Problem-solving agent

A problem-solving agent is a kind of goal-based agent. It solves a problem by finding a sequence of actions that leads to a desirable state. It follows formulate, search, execute:

  1. Goal formulation: decide the goal state from the current situation (a set of world states where the goal is satisfied).
  2. Problem formulation: decide which states and actions to consider (abstract enough: "turn left", not "turn left 30 degrees").
  3. Search: examine different action sequences and find the best one. The result is a solution (a list of actions).
  4. Execution: carry out the solution.
function SimpleProblemSolvingAgent(percept):
    state = UpdateState(state, percept)
    if sequence is empty:
        goal     = FormulateGoal(state)
        problem  = FormulateProblem(state, goal)
        sequence = Search(problem)
    action   = First(sequence)
    sequence = Rest(sequence)
    return action

Assumes the environment is static, fully observable, discrete, deterministic (and sequential).

A well-defined problem has five components

ComponentMeaning
1. Initial stateWhere the agent starts (e.g. "at Arad")
2. Actions / operatorsThe possible actions (set of action-state pairs)
3. Transition model (successor function)What each action does; S(x) = states reachable from x by one action. Initial state + actions + transition model define the state space (all states reachable from the initial state). A path is a sequence of states connected by actions.
4. Goal testChecks if a state is a goal: explicit (x = "at Bucharest") or implicit (Checkmate(x))
5. Path cost function gNumeric cost for a path (performance measure); usually the sum of step costs c(x, a, y) ≥ 0

A solution is a path from the initial state to a goal state. An optimal solution has the lowest path cost. Abstraction means removing irrelevant detail from the state description. Toy problems illustrate methods (puzzles, chess); real-world problems matter to people (design, planning, robot assembly).

Search tree

  • The search finds a solution by exploring the state space as a search tree generated from the initial state and the successor function. The root is the initial node.
  • Expanding a node = applying the successor function to generate its children. Leaf nodes have no (generated) successors. The fringe (frontier / OPEN list) is the set of generated nodes not yet expanded.
  • The search strategy decides which fringe node to expand next. The order of nodes in the fringe defines the strategy.
  • State space ≠ search tree. A state space with two states A and B can give an infinite tree A-B-A-B-... A good strategy avoids such repeated states.
A node has five componentsSTATE, PARENT-NODE, ACTION (applied to parent to get this node), PATH-COST g(n), DEPTH (steps from the root).

5. Uninformed (blind) search strategies

Uninformed search has no information about the number of steps or cost from the current state to the goal; it searches the state space blindly. The strategies are: breadth-first, uniform-cost, depth-first, depth-limited, iterative deepening (and bidirectional).

5.1 Breadth-First Search (BFS)

Expand the shallowest unexpanded node. Fringe is a FIFO queue: new nodes go at the end. All nodes at depth k are expanded before depth k+1.

Fringe in BFS: (1) → (2,3) → (3,4,5) → (4,5,6,7).

  • Complete: yes (if b is finite). Optimal: yes if every step costs the same (e.g. 1); it finds the shallowest goal.
  • Time: 1 + b + b² + ... + bd ≈ O(bd) Space: O(bd), it keeps every node in memory. Space is the bigger problem than time.

5.2 Depth-First Search (DFS)

Expand the deepest unexpanded node. Fringe is a LIFO stack: successors go at the front. Follow the leftmost path to the bottom, then backtrack at a dead end. Backtracking search generates only one successor at a time (even less memory).

  • Complete: no (fails in infinite-depth spaces or loops; complete in finite spaces if repeated states are avoided).
  • Optimal: no (may find a deeper, costlier solution first).
  • Time: O(bm), terrible if m is much larger than d. Space: O(bm), linear. That is its big advantage (118 KB instead of 10 PB for d = 12 in your slides).
  • If solutions are dense, DFS may be much faster than BFS.

5.3 Uniform-Cost Search (UCS / branch and bound)

Expand the node with the lowest path cost g(n) (priority queue sorted by cost so far). The first goal popped is the least-cost solution.

  • Complete: yes (step costs positive). Optimal: yes.
  • If all costs are equal it behaves like BFS. Otherwise time and space depend on the cost of the optimal solution and can be exponential (cheap steps may be explored before useful costly ones).

5.4 Depth-Limited Search (DLS)

DFS with a depth bound l: nodes at depth l are treated as having no successors. Prevents going down an infinite path. Incomplete if the goal is deeper than l; not optimal. Time O(bl), space O(bl).

5.5 Iterative Deepening Search (IDS / IDDFS)

Run DLS with limit 0, then 1, then 2, ... until the goal is found. Combines BFS's completeness and optimality (equal step costs) with DFS's low memory.

  • Repeated work is small: nodes generated = (d)b + (d−1)b² + ... + (1)bd = O(bd), about 1/b of the total.
  • Example, b = 10, d = 5: BFS generates 1,111,100 nodes, IDS generates 123,450.
  • Complete: yes. Optimal: yes if step cost is uniform (finds the shallowest). Space: O(bd), linear.
  • Preferred uninformed method for large spaces with unknown solution depth.

5.6 Bidirectional search

Search forward from the initial state and backward from the goal at the same time, stopping when the two frontiers meet. Time and space O(bd/2) instead of O(bd). Needs a way to generate predecessors and to detect overlap.

Avoiding repeated states

Do not return to the parent; do not create paths with cycles; keep a CLOSED (explored) list of expanded states and skip them. This turns tree search into graph search.

Python code: BFS and DFS on a graph

from collections import deque

graph = {'S':['A','D'], 'A':['B','D'], 'D':['A','E'], 'B':['C','E'], 'E':['B','F'],
         'C':[], 'F':['G'], 'G':[]}

def bfs(graph, start, goal):
    fringe = deque([[start]])          # FIFO queue of paths
    visited = {start}
    while fringe:
        path = fringe.popleft()        # shallowest first
        node = path[-1]
        if node == goal:
            return path
        for nxt in graph[node]:
            if nxt not in visited:
                visited.add(nxt)
                fringe.append(path + [nxt])
    return None

def dfs(graph, start, goal):
    fringe = [[start]]                 # LIFO stack of paths
    visited = set()
    while fringe:
        path = fringe.pop()            # deepest first
        node = path[-1]
        if node == goal:
            return path
        if node in visited:
            continue
        visited.add(node)
        for nxt in reversed(graph[node]):   # reversed so leftmost child is popped first
            fringe.append(path + [nxt])
    return None

print(bfs(graph, 'S', 'G'))   # shortest in number of edges
print(dfs(graph, 'S', 'G'))

6. Heuristics

What is a heuristic?

  • A technique that solves a problem faster than classic methods, or finds an approximate answer when classic methods cannot. A rule of thumb, strategy, trick or simplification that drastically limits search in large problem spaces.
  • At each branching step it evaluates available information and ranks alternatives to decide which branch to follow.
  • It does not guarantee an optimal solution (or even any solution); it gives solutions that are good enough most of the time. We trade one of optimality, completeness, accuracy or precision for speed.
  • Purpose: produce a solution in reasonable time, and bring exponential problems down towards polynomial time. Heuristics are "weak methods" because they are vulnerable to combinatorial explosion.

Heuristic function h(n)

h(n) = estimated cost (distance) from node n to the nearest goal. Also written alongside g(n) = cost from the start to n. Examples: for robot path planning h(n) can be Euclidean distance; for the 8-puzzle, number of misplaced tiles or Manhattan distance. Algorithms that use h(n) to guide the search are heuristic (informed) search algorithms.

Parts of a heuristic search algorithm

State space, initial state, goal test, successor function, and the heuristic function that estimates the distance to the goal and focuses the search.

Example heuristics for the 8-puzzle

Small worked example. Start: 1 2 3 / 4 _ 6 / 7 5 8. Goal: 1 2 3 / 4 5 6 / 7 8 _. Tiles 5 and 8 are misplaced: h1 = 2. Each is one square from its goal: h2 = 1 + 1 = 2. The real solution is 2 moves (blank down, blank right), so h* = 2. Without a heuristic BFS tries all of UP, DOWN, LEFT, RIGHT blindly; with a heuristic you only follow the most promising move.

Admissibility, dominance, informedness

  • Admissible: h(n) ≤ h*(n) for every node, where h* is the true cost to the goal. It never overestimates. A* with an admissible h is optimal.
  • Dominance: if h1 and h2 are both admissible and h2(n) ≥ h1(n) for all n, then h2 dominates h1 (is "more informed") and is better for search. Higher admissible values are closer to the truth, so fewer nodes are expanded.
  • Typical cost (8-puzzle): d = 14: IDS expands 3,473,941 nodes, A* with h1 expands 539, A* with h2 expands 113. d = 24: IDS about 54,000,000,000, A* h1 39,135, A* h2 1,641.
  • Relaxed problems: to invent a heuristic, solve a simpler version with fewer restrictions. Its optimal cost is an admissible heuristic for the original. (8-puzzle where a tile may move to any square gives h1; where a tile may move to any adjacent square gives h2.)
  • Heuristics can also be learned from experience.

Generate-and-test and good generators

Generate a possible solution, test whether it is a real solution (compare with the set of acceptable goal states), and stop if yes, otherwise repeat. A good generator is complete (can generate every solution), non-redundant (no duplicates) and informed (uses knowledge of the search space). Example: a PIN made of three 2-digit numbers has (100)3 ≈ 1,000,000 candidates by brute force; knowing each number is a prime below 100 leaves (25)3 ≈ 15,000.

7. Informed (heuristic) search strategies

Informed search (also called heuristic or directed search) uses problem-specific information (the cost or distance to the goal estimated by a heuristic) so it is more efficient than blind search. Idea: use an evaluation function f(n) for each node as an estimate of its "desirability", and expand the most desirable node first. The fringe is a priority queue sorted by f. Special cases: greedy best-first search and A*.

7.1 Best-first search (greedy)

  • f(n) = h(n). Always expands the node that appears closest to the goal. Uses two lists: OPEN (generated, not yet expanded, kept in a priority queue) and CLOSED (already expanded).
OPEN = [start]; CLOSED = []
loop:
    if OPEN is empty: return FAIL
    n = node in OPEN with smallest h(n); move n from OPEN to CLOSED
    if n is the goal: return path from start to n
    for each successor s of n not in OPEN or CLOSED:
        compute h(s); insert s into OPEN (kept sorted by h)
  • Advantages: fast, uses little memory compared with BFS, finds a solution quickly when the heuristic is good.
  • Disadvantages: not optimal (the path found may not be cheapest), can be incomplete (loops/infinite paths without a CLOSED list), and in the worst case behaves like unguided DFS. Time and space O(bm) worst case. Only as good as the heuristic.

7.2 A* search

Evaluate each node with f(n) = g(n) + h(n).

  • g(n) = actual cost from the start to n. h(n) = heuristic estimate from n to the goal (must be admissible). f(n) = estimated cost of the cheapest solution through n.
  • Uses OPEN and CLOSED lists. Always expands the OPEN node with the smallest f.
  1. Put the start node S in OPEN.
  2. If OPEN is empty, return failure.
  3. Remove the node n with the smallest f(n) from OPEN and put it in CLOSED. If n is a goal, return success (trace the path back to S).
  4. Expand n. For each successor compute f; if it is in neither list, add it to OPEN (if already present with a worse g, update it).
  5. Go to step 2.

Properties of A*

  • Complete (finite branching, positive step costs) and optimal if h is admissible (for graph search, h should be consistent).
  • Optimally efficient: no other optimal algorithm using the same heuristic expands fewer nodes.
  • Drawback: keeps all generated nodes, so memory is exponential. This motivates memory-bounded versions: IDA*, RBFS (Recursive Best-First Search), SMA*.
  • Applications: path finding in games and web maps.

7.3 IDA* (Iterative Deepening A*)

A series of depth-first searches like IDS, but the cut-off is an f-cost threshold, not a depth. First threshold = h(root). In the next iteration the threshold becomes the minimum f-value among nodes that were cut off. Gives an optimal solution with linear memory; some redundant work. Weak if f-values are continuous and very close (each iteration adds only one node).

Python code: A*

import heapq

def astar(graph, h, start, goal):
    # graph[u] = list of (v, step_cost); h[u] = heuristic estimate to goal
    open_pq = [(h[start], 0, start, [start])]     # (f, g, node, path)
    best_g = {start: 0}
    while open_pq:
        f, g, node, path = heapq.heappop(open_pq) # smallest f first
        if node == goal:
            return path, g
        for nxt, cost in graph[node]:
            g2 = g + cost
            if g2 < best_g.get(nxt, float('inf')):
                best_g[nxt] = g2
                heapq.heappush(open_pq, (g2 + h[nxt], g2, nxt, path + [nxt]))
    return None, float('inf')

8. Local (iterative improvement) search

For many optimisation problems the path is irrelevant; we only want a good final state (e.g. TSP, n-queens). Keep a single current state, try to improve it, use constant memory. These are in your slides under informed search, so they can be asked.

8.1 Hill climbing (greedy local search / gradient ascent)

  • Repeatedly move to the best neighbour; stop when no neighbour is better. Keeps only the lowest-h (best) state; irrevocable (no backtracking), unlike best-first which keeps alternatives. "Like climbing Mount Everest in thick fog with amnesia."
  • Much faster, very little memory (O(b)), but not complete, not optimal, and depends on h(n).
ProblemDescription
Local maximum (foothill)A peak higher than its neighbours but lower than the global maximum; search gets stuck

Variants: stochastic hill climbing (choose randomly among uphill moves, steeper moves more likely), first-choice (take the first better neighbour), random-restart (restart from random states; becomes complete with probability 1). Local maxima can also be escaped with random walks or sideways moves.

8.2 Beam search

Keep only the best n nodes (the beam width) on OPEN. n = 1 gives hill climbing; n = ∞ gives best-first search. Local beam search keeps k states and picks the top k of all successors (k parallel hill climbs that share information). Choosing the k successors randomly, biased to good ones, resembles natural selection.

8.3 Simulated annealing

Compromise between hill climbing (incomplete) and pure random search (inefficient). Inspired by annealing: slowly cooling metal into a low-energy state. A temperature schedule T controls randomness: at high T many "bad" moves are accepted; as T cools, fewer. If T decreases slowly enough it reaches the best state.

function SimulatedAnnealing(problem, schedule):
    current = MakeNode(InitialState(problem))
    for t = 1 to infinity:
        T = schedule[t]
        if T == 0: return current
        next = randomly selected successor of current
        dE = Value[next] - Value[current]
        if dE > 0:  current = next                 # better: always accept
        else:       current = next with probability e^(dE / T)   # worse: sometimes accept

8.4 Genetic algorithms (GA)

An adaptation procedure based on natural genetics and natural selection. Two essentials: survival of the fittest and recombination.

  • Chromosome = a string (usually binary) encoding one candidate solution; gene = one bit/attribute. A population is a set of chromosomes. A fitness function scores each.
  1. Initialise a population of random guesses.
  2. For each generation: evaluate fitness; create a new population using the operators below.
  3. Stop when a solution is found or the maximum generation is reached.

1. Knowledge representation (KR) basics

To solve complex problems we need (1) a large amount of knowledge and (2) a mechanism to represent and manipulate it to create new solutions. Humans "know" things and "reason"; representation = how things are stored, reasoning = how knowledge is used (to solve problems and generate more knowledge). Knowledge and reasoning matter especially in partially observable environments.

Facts and representations

  • Facts: truths in some relevant world (what we want to represent). Representation of facts in a chosen formalism: what we can actually manipulate.
  • Two levels: the knowledge level (facts described) and the symbol level (facts represented as symbols a program can manipulate).
  • The two are linked by representation mappings: forward mapping (facts → representation) and backward mapping (representation → facts). English sentences are often used for input/output, so mappings from English to the internal form and back are also needed.
  • Ordinary English is too hard for a program to reason in, so a symbolic representation is necessary.

Types of knowledge

Tacit (implicit)Explicit
Exists inside a human; embodied; informal; hard to articulate, communicate or copy; comes from experience and subjective insightExists outside a human; embedded in artefacts; formal; can be articulated, shared, stored and processed; easy to copy

Problem solving requires converting informal (implicit) knowledge into formal (explicit) knowledge.

Properties of a good KR system

PropertyMeaning
Representational adequacyCan represent all the kinds of knowledge needed in the domain
Inferential adequacyCan manipulate structures to derive new knowledge from old
Inferential efficiencyCan add extra information (hints) that focuses inference in the most promising direction
Acquisitional efficiencyCan acquire new knowledge automatically instead of depending on human input

KR schemes (approaches)

  • Relational knowledge: facts stored as relations/tables like a database (columns of attributes for a set of objects). Simple, but gives little opportunity for inference (cannot answer "who is the heaviest player?" without an extra procedure).
  • Inheritable knowledge: objects organised in a class hierarchy; elements inherit attributes from parents (slot-and-filler structures, semantic networks, frames). To find a value: look at the object, else go up through instance and isa links until a value is found.
  • Inferential knowledge: new facts derived from given ones using formal logic, e.g. ∀x: dog(x) → hastail(x). Strict rules, correctness guaranteed, supports automated theorem proving.
  • Procedural knowledge: the "how to use it" is embedded in the knowledge itself (programs, recipes). Can hold heuristic knowledge and side effects, but problems of completeness, consistency (Fred is a bird so flies... but Fred is an emu), modularity and cumbersome control.

Common KR mechanisms: logic (propositional, predicate), rules, frames, semantic nets. Declarative vs procedural agents: a declarative agent is built by TELLing it facts; a procedural agent has behaviour coded directly as program code (more efficient, less flexible).

Knowledge-based agent

Core is a knowledge base (KB): a set of sentences in a formal language. Two operations: TELL (add a sentence to the KB) and ASK (query what is known). The agent must represent states and actions, incorporate new percepts, update its model, deduce hidden properties and deduce appropriate actions. Design: domain-independent inference engine + domain-specific knowledge base.

2. Propositional logic (Boolean logic)

A proposition is a declarative sentence that is either true or false. Atomic: "The sky is blue", "2 × 2 = 4". Molecular/complex: "The sky is blue and the plants are green".

  • Constants True, False; proposition symbols P, Q, P1,2 are sentences.
  • ¬S (negation), S1 ∧ S2 (conjunction, AND), S1 ∨ S2 (disjunction, OR), S1 → S2 (implication), S1 ↔ S2 (biconditional, IFF).

Semantics terms

  • Syntax: which sentences are well formed ("x + 2 ≥ y" is, "x2 + y >" is not). Semantics: truth of each sentence in each possible world (model).
  • Model: a formally structured world in which truth can be evaluated. M(α) = set of all models in which α is true.
  • Entailment (α ⊨ β): β follows logically from α; in every model where α is true, β is true. KB ⊨ α iff M(KB) ⊆ M(α).
  • Inference: deriving a sentence from the KB by a procedure (KB ⊢i α). Entailment is the needle; inference is finding it in the haystack. Model checking enumerates models to prove entailment.
  • Satisfiable: true under some interpretation. Valid (tautology): true under every interpretation. Contradiction (unsatisfiable): true under none.

Step 1: ¬(¬P ∨ Q) ∨ R. Step 2: (P ∧ ¬Q) ∨ R. Step 3: (P ∨ R) ∧ (¬Q ∨ R). Done.

Limitations of propositional logic

It cannot represent objects or relations between them. "Socrates is a man" and "Plato is a man" become two unrelated symbols SOCRATESMAN and PLATOMAN, so "who is a man?" cannot be answered. It also becomes impractical even for very small worlds (needs one proposition per square per property). This is why we move to predicate logic.

Wumpus world (the running example)

  • PEAS: Performance: gold +1000, death −1000, each step −1, using the arrow −10. Actuators: turn left, turn right, forward, grab, release, shoot. Sensors: breeze, glitter, smell.

Building blocks

  • Constants: name a specific object (Marcus, 3). Variables: x, y. Function symbols: map objects to objects (father-of(Mary)). Predicate symbols: map objects to truth values (greater(5,3), man(Marcus)).
  • Term: constant, variable or function of terms. Ground term: no variables. Atomic sentence: predicate applied to terms. Complex sentence: atomic sentences joined by ¬ ∧ ∨ → ↔. Quantified sentence: adds ∀ or ∃.
  • Well-formed formula (wff): a sentence with no free variables (all bound by quantifiers). (∀x) router(x, y): x is bound, y is free, so not a wff.

Quantifiers

  • Universal ∀x P(x): P holds for all x. Used with → : ∀x student(x) → smart(x) = "all students are smart".
  • Existential ∃x P(x): P holds for some x. Used with ∧ : ∃x student(x) ∧ smart(x) = "some student is smart".
Classic mistakes∀ with ∧ ("∀x student(x) ∧ smart(x)") says everyone in the world is a student and smart. ∃ with → ("∃x student(x) → smart(x)") is true if there is any non-student. Use ∀ with → and ∃ with ∧.
  • Order: same-type quantifiers can be swapped. Mixed order changes meaning: ∀x ∃y loves(x,y) = "everyone loves someone"; ∃y ∀x loves(x,y) = "someone is loved by everyone".
  • Duality (De Morgan for quantifiers): ¬∀x P(x) ≡ ∃x ¬P(x); ¬∃x P(x) ≡ ∀x ¬P(x); ∀x P(x) ≡ ¬∃x ¬P(x); ∃x P(x) ≡ ¬∀x ¬P(x). "Everyone dislikes garlic" = ∀x ¬likes(x, garlic) = ¬∃x likes(x, garlic).

Resolution (proof by refutation)

Resolution proves a statement P from a set of statements F by showing that F ∪ {¬P} is contradictory. Used in theorem proving, logic programming (Prolog), deductive databases.

Step 1: convert to clause form (9 steps)

  1. Eliminate → (a → b ≡ ¬a ∨ b).
  2. Reduce the scope of ¬ to single predicates (De Morgan, ¬¬p = p, ¬∀x P = ∃x ¬P, ¬∃x P = ∀x ¬P).
  3. Standardise variables so each quantifier binds a unique variable (∀x P(x) ∨ ∀x Q(x) becomes ∀x P(x) ∨ ∀y Q(y)).
  4. Move all quantifiers to the left (prenex normal form).
  5. Eliminate existential quantifiers by Skolemisation: ∃y President(y) becomes President(S1) (Skolem constant). ∀x ∃y father-of(y, x) becomes ∀x father-of(S2(x), x) (Skolem function with one argument per enclosing ∀).
  6. Drop the universal prefix (all remaining variables are universal).
  7. Convert the matrix to a conjunction of disjuncts (CNF).
  8. Create a separate clause for each conjunct.
  9. Standardise apart: rename variables so no two clauses share a variable.

Step 2: unification

To resolve, we must match literals such as hate(x, y) and hate(Marcus, z). Unification finds a set of substitutions that makes two literals identical. man(John) and ¬man(John) contradict; man(John) and ¬man(Spot) do not.

  • hate(x, y) and hate(Marcus, z) unify with {Marcus/x, z/y} (the most general unifier), or less generally with {Marcus/x, Caesar/y, Caesar/z}, etc.
  • Unify(L1, L2): if both are constants/variables: identical → NIL; a variable that occurs in the other → FAIL (occurs check); else substitute. Predicate symbols must be the same, with the same number of arguments. Unify argument by argument, applying the substitution found so far to the rest, and combine the substitutions.

Step 3: resolution algorithm

  1. Convert all statements of F to clause form.
  2. Negate the goal P, convert it to clause form, and add it to the clauses.
  3. Repeat until a contradiction is found, no progress can be made, or effort runs out: pick two parent clauses; if one contains T1 and the other ¬T2 and T1, T2 unify, then the resolvent is the union of all other literals with the substitution applied (the complementary pair is dropped); if the resolvent is the empty clause, a contradiction is found and the goal is proved; otherwise add the resolvent to the clauses.

Mini example. KB: man(Marcus); ∀x man(x) → mortal(x). Prove mortal(Marcus).
Clauses: (1) man(Marcus) (2) ¬man(x) ∨ mortal(x) (3) ¬mortal(Marcus) (negated goal).
Resolve (2) and (3) with {Marcus/x}: ¬man(Marcus). Resolve this with (1): empty clause. So mortal(Marcus) is proved.

4. Rule based systems (forward and backward chaining)

Definition and parts

  • A rule based system (RBS, production system) is a system whose knowledge base is a set of IF-THEN rules plus a collection of facts, with an interpreter (inference engine) controlling how the rules are applied to the facts. Rule form: IF <antecedent> THEN <consequent>. If the antecedent is empty, the rule is just a fact. Rules are usually Horn clauses.
  • Knowledge-based system (stores explicit knowledge) ⊃ rule based system (knowledge as rules) ⊃ expert system (rules come from human experts in a domain).
  • The knowledge is separated from the reasoning process, so new systems are easy to build; RBSs are fast, flexible and easy to expand.
ComponentRole
Working memoryHolds the current facts / assertions; if-patterns match assertions here
Rule baseThe IF-THEN rules (stored for efficient access to antecedents)
Interpreter (inference engine)Compares each rule with the facts; when the IF part matches, the rule fires and its THEN part is executed. Does the reasoning
Explanation facility (in expert systems)Tracks the chain of reasoning so the system can explain how an answer was reached (not a "black box")
  • Deduction systems: then-patterns specify new assertions to add to working memory. Reaction systems: then-patterns specify actions.
  • Characteristics: simple human-readable rules, deterministic (same input, same output), transparent, scalable, easy to modify.
  • The inference rule behind it all is Modus Ponens: if P and P → Q, infer Q. (A = "it is raining", A → B = "if raining, carry an umbrella", so B.)

Forward chaining (data driven, bottom-up)

Start from the known facts, find rules whose antecedents match, fire them to add new facts, and repeat until the goal is derived or no rule applies. The reasoning starts from data and ends at the conclusion.

Recognise-act cycle: (1) Match rules whose antecedents are satisfied by working memory; (2) Conflict resolution if more than one matches; (3) Execute the chosen rule's consequent (add the new fact or do the action). Repeat.

Forward proof: start with the facts American(West), Missile(M1), Owns(Nono,M1), Enemy(Nono,America) → derive Weapon(M1), Sells(West,M1,Nono), Hostile(Nono) → all four premises of the first rule hold → Criminal(West).

Keeping a history trace lets the system backtrack if a chosen rule leads to a dead end (a search through a graph of possibilities).

Backward chaining (goal driven, top-down)

Start from the goal (hypothesis) and work backwards: find rules whose consequent matches the goal, then make their antecedents new sub-goals, until sub-goals are known facts. Reasoning is goal-directed. Each step taken is one that definitely helps reach the goal, which is efficient when the start state allows very many actions.

Backward cycle: Match rules whose consequents match the (sub)goal; resolve conflicts; replace the goal by the rule's antecedents.

Weather example (backwards): Goal: chances of rain ← R1 needs temp < 20° and humidity. temp < 20° ← R2 needs sun behind clouds (fact ✓) and air very cool (fact ✓). humidity ← R3 needs air very heavy (fact ✓). All sub-goals proven, so rain is likely.

West example (backwards): Goal Criminal(West) ← American(West) ✓ (fact), Weapon(y), Sells(West, y, z), Hostile(z). Weapon(y) ← Missile(y); Sells(West, y, z) ← Missile(y) ∧ Owns(Nono, y) giving y = M1, z = Nono; Hostile(Nono) ← Enemy(Nono, America) ✓. All proven.

Building a rule based system

  1. Determine the problem.
  2. Establish the rules (from expert knowledge or data analysis).
  3. Implement the rules in a rule-based tool.
  4. Test, evaluate and refine.

Encoding human knowledge into rules is knowledge elicitation. It is hard because experts may not know how they know, are busy, may disagree, some knowledge is hard to codify, and knowledge changes over time.

Examples and advantages

  • Uses: medical diagnosis, fraud detection (amount, location, time), quality control, decision support, elevator control.
  • Advantages: transparency and explainability, efficiency (no large data needed), accuracy when rules are right, flexibility (add or edit rules).
  • Limits (general knowledge): hard to elicit expert rules, cannot learn by itself, large rule sets get hard to maintain, cannot handle situations no rule covers.

5. Semantic networks and frames

Three families of KR: logic (propositional, predicate), network representation (semantic nets) and structured representation (frames).

Semantic network (semantic net)

  • An alternative to predicate logic: a labelled directed graph. Nodes = objects or concepts; links (arcs) = relations between nodes.
  • Common relations (no standard set): INSTANCE (X is a specific example of Y: Elvis instance Human), ISA (X is a subset of Y: sparrow isa bird), HASPART (sparrow haspart tail). Examples: isa(person, mammal), instance(Mike Hall, person), team(Mike Hall, Cardiff).
  • Inheritance: a node inherits properties of the classes above it through isa/instance links.

Comparison example: "Bill is taller than John" with nodes Bill and John and arc taller_than; to show more detail, add primitive nodes h1, h2 (heights) linked by greater_than. Complicated relations are built from primitives.

6. Ontology (ontological engineering)

Origin and meaning

  • From Greek onto = existence / being real, and logia = science / study: "the study of being". Used both in philosophy and in computing.

7. WordNet as a knowledge representation tool

  • WordNet is a lexical database of English built at Princeton University (Cognitive Science Laboratory, under George A. Miller). It groups words into sets of synonyms called synsets, each representing one concept, with a short definition and example sentences. Used by linguists, psychologists, AI and NLP researchers.
  • It works as both a dictionary (definitions, sample sentences) and a thesaurus (conceptual and lexical relations). Machine readable. It does not give pronunciation, etymology, morphology, usage notes or pictures.
  • Four syntactic categories: nouns, verbs, adjectives, adverbs. Basic units include compounds, phrasal verbs, collocations and idioms.
  • Synset vs lemma: a lemma is a word form; a synset is a set of lemmas sharing one sense. A polysemous word (mouse: animal / computer device) appears in several synsets.

Extra: word similarity using WordNet (in your big Unit 2 PDF)

  • Path-based: sim = 1 / pathlen(c1, c2) (shorter path in the hypernym tree = more similar). Leacock-Chodorow: −log(pathlen / 2D), D = depth of the hierarchy.
  • Information-content based: IC(c) = −log P(c), where P(c) is the probability of encountering concept c (or its descendants) in a corpus. Resnik: sim = IC(LCS(c1, c2)), LCS = lowest common subsumer. Lin: 2·IC(LCS) / (IC(c1) + IC(c2)). Jiang-Conrath: distance = IC(c1) + IC(c2) − 2·IC(LCS).
  • Zeugma test checks whether two uses of a word are really different senses (if one verb can sensibly cover both objects, it is one sense).

What is Prolog?

Prolog (PROgramming in LOGic) is a declarative, logic programming language based on predicate logic (Horn clauses). You state facts and rules about the problem; the system answers queries by backward chaining with resolution and unification, searching depth-first with backtracking. Widely used in AI, NLP, expert systems.

Syntax rules

  • Fact: likes(mary, wine). (ends with a full stop). Rule: head :- body. reads "head is true IF body is true"; comma means AND, semicolon means OR. Query: ?- likes(mary, X).
  • Atoms (constants, predicate names) start with a lowercase letter: mary, likes. Variables start with an uppercase letter or underscore: X, Person, _ (anonymous).
  • Lists: [a, b, c]; head and tail: [H|T]; empty list [].
  • Arithmetic: X is 2 + 3. (use is to evaluate; = only unifies). Comparison: >, <, =:=, =\=.
  • Negation as failure: \+ goal. Cut: ! stops backtracking.

Example 1: facts, rules, queries

% facts
parent(tom, bob).
parent(tom, liz).
parent(bob, ann).
male(tom).  male(bob).

% rules
father(X, Y)      :- parent(X, Y), male(X).
grandparent(X, Z) :- parent(X, Y), parent(Y, Z).
sibling(X, Y)     :- parent(P, X), parent(P, Y), X \= Y.

?- parent(tom, bob).        % true.
?- parent(tom, X).          % X = bob ; X = liz.   (type ; for more answers)
?- grandparent(tom, W).     % W = ann.
?- father(bob, ann).        % true.

How a query runs: Prolog tries to match the goal with a fact or a rule head (unification), replaces a rule goal with its body sub-goals (backward chaining), and if a branch fails it backtracks to try the next clause.

Example 2: the classic logic KB

man(socrates).
man(plato).
mortal(X) :- man(X).        % all men are mortal

?- mortal(socrates).        % true.
?- mortal(Who).             % Who = socrates ; Who = plato.

This is exactly the predicate-logic fact man(Socrates) and the rule ∀x man(x) → mortal(x) from Unit II, now executable. It answers "who is a man?", which propositional logic could not.

12. Bag of Words (BoW) model

  • The simplest vector space representation. Each text document is represented as a numeric vector in which each dimension is a specific word from the corpus, and the value is its frequency in the document (or 1/0 for occurrence, or a weight). The document is literally a "bag" of its words, ignoring word order, sequence and grammar, but keeping frequency.
  • Used for text classification, document similarity, clustering and sentiment analysis (e.g. words like "fabulous" and "excellent" suggest a positive review; "annoying" and "poor" a negative one).
  • "Bag of Words is nothing but term frequencies."

Three steps to build a BoW

  1. Preprocess: lower-case, remove punctuation.
  2. Build the vocabulary of all unique words in the corpus.
  3. Vectorise: one column per vocabulary word, one row per document; fill in counts (or 1/0).

N-grams

BoW loses word order. Using N-grams (mostly bigrams, pairs of consecutive words) keeps some local order ("not good" vs "good"). But the matrix becomes huge and sparse.   • No semantic information: "good" and "excellent" are unrelated columns; no word associations.

13. TF-IDF model

A high raw count does not mean a word is more important. TF-IDF (Term Frequency, Inverse Document Frequency) "normalises" term frequency by weighting each term by the inverse of how many documents contain it. A word frequent in one document but rare across the corpus is informative; a word frequent everywhere ("the", "is") gets weight near 0.

Formulae TF(t, d) = (number of times term t appears in document d) / (total number of terms in d)
IDF(t) = log( N / n ), N = number of documents in the corpus, n = number of documents containing t
TF-IDF = TF × IDF

TF-IDF rises with how often a word appears in the document, and falls with the number of documents that contain it.

Visual intuition (four documents)

Documents: "I have a puppy", "I have a cat", "I have a kitten", "I have a dog and I have a pen". "have" appears in all 4 documents, so idf(have) = log 1 = 0, and it vanishes from the TF-IDF vector. "puppy" and "cat" each appear in 1 of 4, so idf = log 4 and tf-idf(puppy) = tf-idf(cat) = log 4. In BoW "have" was the biggest coordinate (2 in the last document); in TF-IDF it disappears and the rare, meaningful words stand out.

  • Uses: information retrieval and search ranking, document classification and categorisation, summarisation, feature extraction for ML.
  • Issues: still high-dimensional and sparse; no context or word order; no semantics (synonyms are unrelated); domain dependent (weights vary with the corpus); ignores word associations.

14. Word embeddings: introduction

NLP models need numbers, not text. Word embedding is a class of techniques where each word is represented as a real-valued vector in a continuous vector space: a dense, low-dimensional representation (e.g. 50 to 300 dimensions) as opposed to sparse one-hot vectors with one dimension per vocabulary word.

  • Designed so that vectors capture similarity of meaning, morphology and context: words used in similar contexts get nearby vectors (the distributional hypothesis).
  • The captured relations help downstream tasks: chatbots, summarisation, information retrieval, translation.
  • Generated by co-occurrence matrices, dimensionality reduction, or neural networks. Two broad families: frequency-based (BoW, TF-IDF, co-occurrence matrix, GloVe's matrix) and prediction-based (Word2Vec).

Earlier representations and why they are not enough

  • One-hot encoding: vector of vocabulary size with a single 1. Huge, sparse, no notion of similarity (every pair of words is equally distant).
  • Vector space model / count-based (BoW, TF-IDF): sparse; capture limited information, ignore word context.
  • Co-occurrence matrix: counts how often words appear near each other within a context window. Example, window of 1, for "India won the match. I like the match.": India-won 1, won-the 1, the-match 2, I-like 1, like-the 1. The matrix is V × V and still sparse.
  • Limitations of all of these: sparse; context limited or absent; one single representation per word in every context (no senses); cannot do semantic reasoning; context is predetermined; long-term dependencies are not captured.

Distributional representation: the key idea

Instead of one dimension per word, give every word a vector of, say, 300 numbers. The meaning of a word is spread across all the dimensions, and each dimension contributes to many words. If dimensions were labelled (royalty, masculinity, femininity, age), "king" would score high on royalty and masculinity, "queen" on royalty and femininity. Similarity between words is measured by cosine similarity of their vectors.

15. Word2Vec

  • Proposed by Mikolov et al. (Google), 2013. A two-layer shallow neural network trained to learn the contextual relationship between words; contextually similar words end up near each other. Unsupervised (the text itself gives the training signal) and based on word co-occurrence in a sliding window.
  • Context = the words in a sliding window around the word under consideration. Window size 2 means 2 words to the left and 2 to the right. Example: "India is now inching towards a self reliant state": for centre word "inching", window 2 gives context {is, now, towards, a}.
  • Two variants: CBOW and Skip-gram.

CBOW (continuous bag of words)

  • Goal: given the context words, predict the centre word wt. Word order within the context is ignored (so it is like BoW over the window).
  • Architecture: (1) one-hot vectors of the context words wt−2...wt+2 are the input; (2) multiplied by a projection (embedding) matrix P of shape V × D (V = vocabulary size, D = embedding size), which just selects the row of each word; (3) the context vectors are averaged into one D-dimensional vector C; (4) multiplied by an output matrix M of shape D × V to give V scores; (5) softmax converts them to probabilities; (6) trained with cross-entropy loss against the one-hot vector of the true centre word.
  • After training, the rows of P (the learned weights) are the word embeddings.

Skip-gram

  • Goal: given the centre word wt, predict the surrounding context words wt−2...wt+2.
  • Objective: maximise the average log probability of the context words: J(θ) = (1/T) Σt Σ−c ≤ j ≤ c, j ≠ 0 log p(wt+j | wt).
  • Softmax model: p(o | c) = exp(uoT vc) / Σw=1..V exp(uwT vc), where every word has two vectors: v (as centre/"input") and u (as context/"output"). Parameters θ are all v and u vectors (2dV numbers), trained by gradient descent θj = θj − α ∂J/∂θj. The final word vector is often v + u.

Negative sampling

The full softmax over V words is expensive, so training with negative sampling is more common. Real (centre, context) pairs like (India, the), (India, now) are positive samples; random "corrupted" pairs like (India, reliant) or (India, state) are negative samples. The task becomes a logistic regression that classifies a pair as a true combination or a corrupt one. Negatives are sampled so that less frequent words are picked more often.

Reasoning with word vectors (analogies)

The learned vectors capture regular relationships as constant vector offsets. Most famous: vector(king) − vector(man) + vector(woman) ≈ vector(queen). Similarly xapple − xapples ≈ xcar − xcars (singular/plural), and man : woman :: uncle : aunt (gender). Analogy a : b :: c : ? is solved by finding the word x maximising the cosine similarity between wx and (wb − wa + wc). Other relations found: country–capital (France–Paris, Japan–Tokyo).

from gensim.models import Word2Vec

sentences = [["india","won","the","match"], ["i","like","the","match"],
             ["india","is","now","inching","towards","a","self","reliant","state"]]

# sg=0 -> CBOW, sg=1 -> Skip-gram; window = context size; vector_size = D
model = Word2Vec(sentences, vector_size=50, window=2, min_count=1, sg=1, negative=5)

print(model.wv["india"][:5])                  # the dense vector
print(model.wv.most_similar("match", topn=3)) # nearest words (cosine)
# analogy on a large pretrained model:
# model.wv.most_similar(positive=["king","woman"], negative=["man"])  -> queen

16. GloVe (Global Vectors for Word Representation)

  • An unsupervised learning algorithm for word vectors, built on a word-word co-occurrence matrix computed over the whole corpus, so it captures global statistics. It combines the best of two model families: local context window methods (Word2Vec) and global matrix factorisation (LSA).
  • It captures (1) a statistical measure from the co-occurrence matrix, and (2) context through neighbouring words. Vector direction and angle reflect semantic and syntactic relations.
  • Idea: factorise the co-occurrence matrix X (words × context) into a word-feature (embedding) matrix and a feature-context matrix: X ≈ W × W̃.

How GloVe learns: ratios of co-occurrence probabilities

It uses word-word co-occurrence probabilities as the signal. Authors' example with target words ice and steam:

Probabilityk = solidk = gask = waterk = fashion
P(k | ice)1.9 × 10−46.6 × 10−53.0 × 10−31.7 × 10−5
P(k | steam)2.2 × 10−57.8 × 10−42.2 × 10−31.8 × 10−5
P(k | ice) / P(k | steam)8.98.5 × 10−21.360.96

Ice goes with solid, steam with gas. Water (related to both) and fashion (irrelevant to both) give ratios near 1. Only the ratio cancels out noisy words like water and fashion: large ratio = related to ice, small = related to steam, near 1 = not discriminating.

Objective function

Xij = number of times word j occurs in the context of word i; Xi = total count of context words around i; Pij = P(j | i) = Xij / Xi. The model aims for F(wi, wj, w̃k) = Pik / Pjk. This leads to the weighted least-squares cost:

J = Σi,j=1..V f(Xij) · ( wiT w̃j + bi + b̃j − log Xij )2
  • V = vocabulary size; wi, bi = vector and bias of word i; w̃j, b̃j = context vector and bias. The dot product of two vectors is trained to match the log of their co-occurrence count.
  • Weighting function f(X) must: be 0 when X → 0, be non-decreasing (so rare co-occurrences are still discriminated), and not over-weight very frequent pairs. Chosen as f(X) = (X / Xmax)α if X < Xmax, otherwise 1.

Practical notes

  • Computational bottleneck: building a huge V × V matrix; cost depends on the number of non-zero entries.
  • Distant word pairs contribute less to the count (they say less about the relationship).
  • The model produces two sets of vectors, W and W̃; the average of both is used as the final embedding.
  • Pre-trained GloVe vectors are freely available (e.g. 50-, 100-, 200-, 300-dimensional; trained on billions of tokens), so you usually do not train from scratch. Example: 'the' → a dense vector like [−0.123, 0.353, 0.652, −0.232] (4-d for illustration).
import numpy as np

# load pretrained GloVe (e.g. glove.6B.100d.txt: "word v1 v2 ... v100" per line)
emb = {}
with open("glove.6B.100d.txt", encoding="utf8") as f:
    for line in f:
        parts = line.split()
        emb[parts[0]] = np.asarray(parts[1:], dtype="float32")

def cos(a, b): return a @ b / (np.linalg.norm(a) * np.linalg.norm(b))
print(cos(emb["king"], emb["queen"]))             # high
v = emb["king"] - emb["man"] + emb["woman"]       # analogy vector, closest word ~ queen
